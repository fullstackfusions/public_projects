## 3. Adopting Day 0 into Terraform (14:10–14:12)

- Inventory first: 2 buckets (web in us-east-1, trail logs in us-east-2), OAC, distribution, ACM cert, trail. Each bucket has a policy, public access block and `BucketOwnerEnforced` ownership, and no versioning, lifecycle or website config. An older expired `fullstackfusions.com` cert predates this project and was left alone.
- `infra/live/imports.tf`: 12 `import` blocks, then `terraform plan -generate-config-out=generated.tf`. The generated file failed validation on CloudTrail's event selectors ([gotchas](gotchas.md) #15) but was written anyway.
- Rewrote it into `web.tf` and `trail.tf`: references instead of IDs (the bucket policy points at `aws_cloudfront_distribution.web.arn`, the origin at `bucket_regional_domain_name`, the cache policy looked up by name `Managed-CachingOptimized`), and no nulls or empty lists. The trail ARN in the log bucket's policy is built by name, because the trail can't be created before the policy exists (a reference would be a cycle).
- `terraform plan` → **12 to import, 0 to add, 0 to change, 0 to destroy**. Applied at 14:11:55; a second plan says "No changes"; `curl -sI https://chaperone.fullstackfusions.com` → `HTTP/2 200` throughout. `imports.tf` deleted after.
- Noticed while reading the generated config: the trail has **log file validation off** (`enable_log_file_validation = false`), and the trail bucket has no lifecycle, so logs are kept forever. Both open below.

## 5. Rules, model, sessions: 57 tests (14:13–14:18, fixed at 14:26)

- `backend/chaperone/rules.py`: six risk classes as pure functions. Public exposure inspects the payload: bucket policies (Principal `*` without a condition), public access block removed or weakened, ACLs, security groups open to `0.0.0.0/0` or `::/0`, Lambda URLs with `authType NONE`, public snapshots and AMIs, SQS/SNS policies. Lambda's versioned event names (`AddPermission20150331v2`) are normalized. `iam:PassRole` is left out on purpose: it's a permission check and never appears in CloudTrail.
- `model.py`: record → item; `sessions.py`: sessions built at read time ([D-020](decisions.md)).
- Tests run on the recorded events: Day 0's CloudFront-only bucket policy and the EventBridge-only SQS policy must **not** count as public; the probe cleanup must count as destructive; every MCP-made API call must appear once, under its tool call.
- Rebuilt from its own CloudTrail, Day 0 came back as two sessions: the hello-world build (10 tool calls, riskiest action a write) and the EventBridge probe (riskiest action destructive: deleted rule, removed targets, deleted queue), split by a 41-minute gap. `s3:PutObject` shows as "unseen": only MCP's downstream list knows about it.
- **Video beat:** the Day 0 replay, generated by the thing Day 0 was about.

## 6. The pipeline goes live (14:19–14:26)

- `infra/live/pipeline.tf`: DynamoDB `chaperone` (provisioned 5/10, TTL 90 days), Lambdas `chaperone-ingest` and `chaperone-poller` (Python 3.13, arm64, 14-day logs, least-privilege inline policies), EventBridge rule with `ENABLED_WITH_ALL_CLOUDTRAIL_MANAGEMENT_EVENTS` and an `$or` pattern that drops Chaperone's own `chaperone-*` roles, and a `rate(1 minute)` schedule for the poller. 15 resources in 35 s (14:19:53).
- The poller also has a **backfill** mode (`{"backfill_user": …, "lookback_minutes": …}`): on install, Chaperone can show history from before it existed.
- The first backfill failed: `agent` is a DynamoDB reserved word ([gotchas](gotchas.md) #17). The scheduled run had already stored 19 sign-ins, because sign-ins skip that clause.
- After the fix: **563 events backfilled**; EventBridge delivering within ~10–30 s of each call; zero ingest errors.
- The first live read-back found three things: the actor's agent flag was lost to out-of-order writes; 558 Terraform calls counted as generic `sdk` traffic ([D-021](decisions.md): an agent is known by its identity); and 72 "errors" that were all Terraform probing optional S3 settings ([gotchas](gotchas.md) #18). Fixed with an unconditional agent-flag write and a `denied` / `not_found` / `other` error class, plus 8 new tests.
- One apply was blocked by Claude Code's auto mode for using `-auto-approve` without a reviewed plan ([gotchas](gotchas.md) #19); from then on it was always plan file → read → apply.
- Result: three sessions for the agent. Today's reads **702 API calls, 558 through Terraform, 0 denied, riskiest action identity escalation**, because the agent put inline policies on the Lambda roles it had just created. Chaperone's first finding is about its own build.
- **Video beat:** the moment the recorder recorded its own construction. Show the session list with today's session flagged amber for `iam:PutRolePolicy`, then explain why that flag is right.

## 9. Who acted, how, and proving nothing is missed (18:28–18:55)

- Mihir asked for every event to be labelled human, agent or MCP. First a coverage check, CloudTrail vs stored for 3 hours: humans 46/46, MCP tool calls 2/2, agent 85/97, AWS services acting on their own 0/~960. The 12 missing agent events were `kms:Decrypt` calls Lambda made for the agent during a deploy: EventBridge never delivered them ([gotchas](gotchas.md) #20).
- Design ([D-024](decisions.md)): MCP is a channel, not an actor. Each event gets `actor_type` (human, agent, workload, service), `via` (mcp, console, cli, terraform, ...) and `operated_by`. An agent on a person's identity through MCP is flagged `agent_on_human_identity`, the case a three-way label would hide. Capture widened to federated, web-identity (CI), cross-account and AWS-service identities.
- Loop guard: AWS services assuming `chaperone-*` roles excluded in the event pattern itself; 8 cases checked with `TestEventPattern` before applying ([gotchas](gotchas.md) #21).
- Reconcile: the poller re-reads each agent's activity in all 17 regions (a fifth per run).
- Performance trail: first reconcile run 69.6 s; the backfill hit the 90 s timeout. `LookupEvents` was fast (1,000 events in 4 s); DynamoDB was not: 2,755 write throttles on 10 provisioned WCU. Batch writes, one actor update per run, and on-demand with a 100-unit cap ([D-025](decisions.md), [gotchas](gotchas.md) #22).
- The MCP sandbox caps results at 1,000 items, so an in-sandbox coverage count read "520/629" for the agent. A local, fully paginated check across all 17 regions for 18:34–18:43: **agent 651/651, human 2/2, sign-ins 29/29, AWS services 23/23**; only misses were 9 KMS crypto calls by AWS services on their own (KMS events never reach EventBridge here; for agents the reconcile covers them).
- New identity type found: `IdentityCenterUser`, 57 `sso:GetRoleCredentials` an hour from hermes: the agent's tooling exchanging its SSO token for role credentials. Chaperone now maps the Identity Center user to the role session it acts as (`IDC#<userId>`) and files these as sign-ins on the agent's timeline.
- `GetRoleCredentials` was still 0/1 after the change (EventBridge again, apparently), so the poller now fetches it from the Identity Center region every minute, like the SAML sign-ins. Final exact check, 18:50–18:57, all 17 regions: **agent 222/222, Identity Center credential fetches 12/12, SAML sign-ins 12/12, AWS services 29/34**; the 5 misses are the known KMS gap.
- **Video beat:** "Is it really recording everything?" The coverage table, the 1,000-item sandbox trap, and the moment the exact count reads 651/651.

## 11. Access Analyzer vs Chaperone's preview (19:20–19:30)

- The Access Analyzer job for the 14:07 build session (`00000000…`, window 14:06:23–14:56:10, all regions) ran **19:14:44 → 19:18:11: 3 min 27 s**. Result `isComplete: false`, 13 statements, 75 actions, resource ARNs as placeholders. Chaperone's preview is instant, from the same 936 recorded items.
- First comparison: 67 shared, 6 only in the preview, 8 only in Access Analyzer. Every difference was traced to its CloudTrail events. Four were Chaperone bugs ([gotchas](gotchas.md) #27, #28):
  - Terraform's probes of optional bucket settings fail with `NoSuchCORSConfiguration` and similar (18 calls each). The preview dropped every failed call; a not-found error still means the call was allowed. Now only access-denied calls are dropped.
  - Event names that differ from IAM actions: `ListBuckets` → `s3:ListAllMyBuckets`, `GetBucketCors` → `s3:GetBucketCORS`, `GetBucketReplication` → `s3:GetReplicationConfiguration`.
  - 66 KMS calls (`Decrypt`, `Encrypt`, `DescribeKey`) that Lambda made itself under the agent's identity (`invokedBy: lambda.amazonaws.com`). Access Analyzer leaves them out, correctly: the agent never called KMS. Now listed separately under "made by AWS services".
- After the fix: **72 of 75 shared**, and `ValidatePolicy` on the preview gives **0 findings**. What's left is where each tool sees something the other can't:
  - **Access Analyzer misses** `logs:FilterLogEvents` (18 successful management events, CLI and MCP, inside the window) and `s3:ListTagsForResource` (18, Terraform). A policy built only from its output would break the agent's log tailing and Terraform's bucket reads.
  - **Access Analyzer adds** `iam:CreateServiceLinkedRole`, `lambda:PassCapacityProvider` and `organizations:ListAWSServiceAccessForOrganization`, with no CloudTrail event for any of them in us-east-1 or us-east-2. My guess is related permissions for actions it did see; its docs don't say.
  - **Both miss** `iam:PassRole`: AWS's docs say CloudTrail doesn't track it, but both `CreateFunction` calls needed it. Chaperone now reads the role ARN from the request (`chaperone-ingest`, `chaperone-poller`) and adds a `PassedInSession` statement scoped to those two roles ([gotchas](gotchas.md) #29). Access Analyzer can't do this: it reads the permission, not the request.
- With `includeServiceLevelTemplate`, Access Analyzer also lists six services at service level only (`access-analyzer`, `cloudformation`, `cloudwatch`, `ec2`, `kms`, `pricing`). Several look like this evening's work, outside the job window. My guess is that this part comes from IAM last-accessed data, which isn't limited to the window, so the console labels them "services used, no action detail".
- The API's `/api/least-privilege` and `/api/review` now return a `comparison` block: shared count, only Chaperone, only Access Analyzer, service-level only, and PassRole recovered. 99 tests (two new, built from these exact differences). Decision: show both, and say what each one missed ([D-027](decisions.md)).
- **Video beat:** "Is AWS's own tool right?" The 3½-minute wait against an instant preview, the diff table going from 14 differences to 5, then `FilterLogEvents`: 18 real calls that AWS's generated policy would have denied.

## 12. The MCP server: an agent reviews its own work (19:35–19:45)

- Design ([D-028](decisions.md)): the MCP server is a thin stdio client over the same API the console will use, signed with SigV4 by whatever AWS credentials it runs with. Needs only `lambda:InvokeFunctionUrl`; never touches DynamoDB or CloudTrail. `session_id="me"` resolves from the function URL's IAM auth (`requestContext.authorizer.iam.userArn`) to the caller's latest session.
- The full session timeline is too big for an agent (936 items for the 14:07 session), so the query layer gained `answers.py`: compact answers with repeats collapsed (Terraform re-reads everything on each plan) and lists capped. New routes `/api/what-happened` and `/api/risky`; every per-session route accepts `id=me`.
- Five tools: `list_sessions`, `what_did_the_agent_do`, `risky_calls`, `review_session`, `least_privilege` (the only one that can write: it can start an Access Analyzer job). Read-only tools carry `readOnlyHint`.
- `risky_calls` implements yesterday's idea: `on_resource_created_this_session`. On the live session it marks `PutRolePolicy` on `chaperone-access-analyzer` (a role that session built) and leaves `chaperone-poller` unmarked (built in the 14:07 session).
- Truncated parameters (big inline policies are cut at the size cap) hid the target of a `PutRolePolicy`; the target is now read from the raw text.
- The MCP Python SDK is at 2.2 now: `FastMCP` is `MCPServer` (`mcp.server.mcpserver`), fields are snake_case, and only `ToolError` messages reach the model; any other exception shows as "Error executing tool" ([gotchas](gotchas.md) #30).
- End-to-end smoke test (a real MCP client over stdio, all tools, live data): 2–15 KB per answer, 3.5–8 s. Registered in Claude Code on hermes (`claude mcp add chaperone`, local scope): **Connected**. 103 tests.
- **Video beat:** the signature moment from the plan. At the end of a task, the agent calls `risky_calls("me")` on its own session and reads back the `PutRolePolicy` it made, with "on a role this session built".
